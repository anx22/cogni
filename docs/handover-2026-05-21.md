## Offenster Bug: Entity-Rotationsreset (Prio 1)

**Symptom**: Beim Bewegen des Cursors über die Entity setzt sich die Rotationsanimation mehrfach zurück → sichtbares Zucken/Ruckeln.

**Root Cause** (analysiert, noch nicht gefixt):

In `src/components/entity/Entity.tsx` Zeile 171–173:

```typescript
useEffect(() => {
  setSample(samplePreset(presets[internal])); // Math.random() → neue CSS-Werte
}, [internal, presets]); // ← presets in deps ist das Problem
```

`presets` kommt aus `useOrbPresets()` → `useMemo([values])` → `values` aus `useNamespace("orb")`.
`values` wechselt die Referenz nach dem initialen async DB-Load von `app_settings` (100–500ms nach Mount). Dieser Wechsel feuert den Effect, generiert neue Zufallswerte für `--animation-duration` + Farben, und die CSS-Animation `siri-orb-rotate` startet von vorne.

Das timing ist zufällig — passiert halt oft während der User gerade den Cursor bewegt.

**Fix (minimal, klar)**:

In `Entity.tsx` die `presets`-Dependency durch ein Ref ersetzen:

```typescript
// Ref hält immer aktuelle Presets, ohne Re-Sampling auszulösen
const presetsRef = useRef(presets);
useEffect(() => {
  presetsRef.current = presets;
}, [presets]);

// Nur re-samplen wenn der State wechselt (idle → hover → etc.)
useEffect(() => {
  setSample(samplePreset(presetsRef.current[internal]));
  // eslint-disable-next-line react-hooks/exhaustive-deps
}, [internal]);
```

Konsequenz: OrbLab-Preset-Änderungen gelten erst beim nächsten State-Wechsel (akzeptabel, OrbLab ist Debug-Tool).
